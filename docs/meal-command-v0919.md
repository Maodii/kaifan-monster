# 0.9.19 记餐协作与方式筛选修复

普通对话中的明确记餐指令使用共享本机规则生成草稿，例如“我今天吃了辣椒炒肉帮我记入晚餐并帮我同步一下图片”。两端都提供核对记录/添加照片入口，进入现有记餐编辑器，不再为该句请求通用聊天回答。

只读取当前输入，不执行模型文本。支持今天/昨天、明确餐次、明确花费与用餐方式；日期或餐次含混时提示补充。未知花费与热量不由助手虚构。未指明用餐方式时沿用现有编辑器的默认外食值，用户可调整。保存前不写业务记录、不扣库存、不读取相册、不上传照片。照片在编辑器主动拍摄/选择，之后沿用既有照片上传流程；本次没有改变同步策略。账号变化拒绝旧草稿操作，已有记餐编辑器打开时不覆盖。

Android 用餐方式筛选使用独立样式，选中与未选中保持一致的高度、基线、内边距和居中方式。普通390宽屏完整显示六项；窄屏或大字可横向滚动。Harmony 使用等高居中按钮。

验证：Android宿主实测默认对话→草稿→编辑→显式保存、账号隔离、拒绝注入/否定/引用、8组屏宽与字体组合；共享核心13组、库存/菜谱协作9组、计划/记餐流程7组和启动隐私10组通过。Harmony模拟器覆盖安装后使用用户原句测试，成功打开带拍照/相册入口的编辑器，未保存该测试记录。无真实模型调用或云端照片上传。Android未连接真机。
