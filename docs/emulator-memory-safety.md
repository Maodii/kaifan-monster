# 模拟器内存异常

## 进一步取证结论（2026-11-05）

已确认宿主机出现压缩内存资源耗尽，不能把此前模拟器退出直接归因为模拟器泄漏。读取 `/Library/Logs/DiagnosticReports/` 下11月4日、5日共13份 Apple JetsamEvent：所有快照的 `largestProcess` 均是 `Codex (Service)`，PID19507。按报告的 `rpages × pageSize(16384)` 换算，该进程11月5日约12.47–12.89GiB，11月4日已约12.96–13.02GiB；同时间 Codex Renderer 约5.9GiB，Virtualization 约5.6GiB。进程内存计量包含压缩等核算，不能把进程数字简单相加称为独占的物理RAM。

11月5日10:37–10:43的多个报告明确包含 `vm-compressor-space-shortage`，loginwindow于10:31和10:36启动低内存提示，并记录其他应用因低内存暂停。由此可确认“多进程内存负载过高→压缩内存资源不足→系统低内存处置”的故障机制；Codex Service是快照中最大内存负担。

同期Emulator进程93395的采样为4.81→4.62→4.61→4.50→4.49→4.48→4.86GiB，没有记录到持续暴涨。该实例使用4GiB客户机RAM，启动后的主机开销不能单凭4–5GiB认定泄漏。另一个实例23228的单次采样5.25GiB、生命周期峰值5.63GiB。采样不能排除两次记录间的尖峰，但现有证据不支持“模拟器无限泄漏已确认”。

Codex自身日志在10:47:06记录GPU子进程被终止并可恢复；此后PID19507已不存在。日志未提供它与该PID的直接关联，所以不能把“异常Service就是GPU”写成确定事实。缺少异常Service当时的内存转储和调用栈，具体对象保留或泄漏触发点仍未定位。官方文档页面取证请求返回403，未用网络资料替代本机证据。

逐份源报告路径、SHA256、时间、页大小和进程数值保存在 `work/reports/memory-root-cause.json`；未复制整份系统报告、未重启模拟器、未终止其他项目进程。处置优先释放宿主机内存负担（保存工作后重启Codex，必要时重启Mac），而非改写应用动画或清空模拟器数据。脚本保护只作为额外防护。

## 初次检查记录

用户确认暴增进程为 Emulator。现有证据不能把模拟器泄漏归因于应用手势或动画。

2026-11-05 本机为16GiB内存，排查时 macOS 内存压力级别2（警告），交换空间使用约38GiB。Emulator 已退出，未捕获暴增瞬间的物理内存曲线。设备日志记录10:22 guest no response/system freeze；末次设备内存快照约1.7GiB已用、2.1GiB空闲，快照中没有应用进程。这是单次快照，不能排除其他时刻的问题。

历史11月4日崩溃报告为 Qt 平台集成初始化失败并 SIGABRT，不能当成本次内存暴增的证据。此前启动日志还记录过 loginwindow 发出的 SIGTERM，亦不能单凭它判断是内存耗尽。

## 本项目启动保护

只读检查：`python3 scripts/safe-emulator.py`

明确启动：`python3 scripts/safe-emulator.py --start`

启动前要求系统内存压力正常，交换空间使用不超过物理内存，且没有已运行的 Emulator。只启动现有 Mate 90 Pro，冷启动保留数据，不重置、不清理、不修改全局模拟器配置，不打开窗口。

每2秒检查独立进程组的 macOS physical footprint（包含压缩内存计量），达到6GiB上限、系统严重内存压力，或启动90秒后占用超过4GiB且15秒增长超过1.5GiB时，停止本脚本启动的进程组。监测失效也停止该实例，不无限重试。记录只更新 `work/reports/emulator-memory-guard.json` 一份文件。

这是轮询式保护及诊断手段，不能保证在两次采样之间阻止极快的内存暴增，也不是模拟器泄漏修复。通过 DevEco 直接启动的实例不受脚本保护；脚本不会接管或终止其他项目的模拟器。当前系统内存压力未解除，不做复现压测。

已验证本机 physical footprint API、绝对上限、压力判断、快速增长、启动宽限和正常稳定用量分支。当前真实预检拒绝启动；未验证真实模拟器越限后的终止路径。

下一步在内存压力正常后，通过受保护启动采集曲线，先比较未打开应用的空闲阶段，再比较应用首页和手势切页阶段。发生过整机卡死时，先保存其他项目工作，通过系统重启释放累积交换占用，再进行受控验证。
