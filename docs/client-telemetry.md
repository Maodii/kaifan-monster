# 安卓与鸿蒙客户端埋点

2026-11-17：双端共用 `client/entry/src/main/ets/model/ClientTelemetry.ets`，安卓通过现有共享核心构建流程生成，不维护两套统计协议。服务端接收接口与管理端展示已部署；手机端需要安装含本次代码的新版本，本任务未签名/发布商店安装包，也未做真机验证。

## 开关和数据范围

入口：我的 → 关于与支持 → 帮助改进体验（可选）。默认关闭，独立于云功能授权；仅在主动开启、同意当前隐私政策、已登录时收集和发送。未登录、本机模式、未同意或关闭开关不记录待发事件。隐私政策版本已更新，升级后需按现有流程重新确认云功能授权。

| 事件 | 实际接入位置 | 字段 |
|---|---|---|
| app_open | 前台进入，或登录/开启开关后首次符合条件的活动 | 事件时间、随机事件ID |
| page_view | 鸿蒙页面/主Tab切换；安卓实际页面渲染去重；助手入口 | 固定页面分类，不含菜谱ID或用户输入 |
| ai_send | 双端共享 AssistantLive 开始云端提问 | ask/week/rescue/meal任务类型 |
| ai_retry | 失败后相同请求重试，或用户明确重新生成 | 任务类型 |
| ai_cancel | 取消正在进行的共享助手请求 | 取消及已等待时间 |
| ai_complete | 共享助手收到最终回答或失败 | model/fallback/error、端到端耗时、首次可展示增量耗时 |
| photo_upload | 共享 Cloud 的用餐照片上传流程，覆盖登记、传输、确认 | success/error和总耗时；每张照片单独计数 |

每批附带 android/harmony 和应用版本。没有聊天原文、回答正文、搜索词、照片、签名链接、文件路径、设备指纹或持久设备标识。事件ID为短期随机值，仅用于去重，不是用户或设备标识。身份由服务器验证当前登录凭据，客户端不能指定任意用户。

不统计未登录/本机模式用户，不统计系统启动但未开启统计的用户；app_open是符合条件的前台/首次活动事件，不等于安装量或完整DAU。客户端是可选测量，不用于扣额度、计费或安全判断。首字耗时以共享轮询模块收到首段可展示文本为准；未提供增量时记未知，不伪造为0。

当前照片事件覆盖用餐照片上传，不含头像上传或相册备份。没有接入客户端原始崩溃堆栈、广告归因或跨应用追踪SDK。

## 传输与隔离

- 仅内存队列，最多60条，每批20条，约5秒发送一批；不写磁盘，不后台常驻补传。
- 同一失败批次最多尝试3次，指数退避，最长60秒；失败不阻塞业务。进程退出、队列溢出或超过尝试次数可能丢失统计，所以不能视为精确账单。
- 切换账号、退出、切换服务地址、撤回云同意或关闭统计时清除待发记录；未完成的旧操作不会记到新账号下。
- 已经发出的网络请求无法保证撤回；停用阻止后续新上报，不声称能撤销服务器已经接收的数据。
- 进入后台时尽力发一次，停止定时重试；系统随时可能暂停应用。重返前台丢弃超过一天的旧记录。
- `/api/v1/telemetry/events` 强制登录，DTO严格字段白名单，每批1–20条，平台、事件、页面、结果均为枚举，时间戳允许前后一天以内，每分钟最多12批。
- 同一用户同一事件ID重发不重复入库，不同用户的事件去重空间相互独立。
- 服务端原有90天分批保留、账号注销删除及管理员/演示账号分类继续适用。

## 管理端查看

使用分析 → 双端体验统计（用户自愿开启），按平台、版本、事件、页面、任务、结果显示次数与平均耗时。沿用时间区间和测试账号筛选。与服务器AI结果分开统计，不能相加；原有“云端活跃”口径排除客户端事件，避免仅因埋点请求而扩大云端业务用户数。
