# 完整整改与发现功能验收

当前源代码面向本地优先：库存、记餐、计划、私房菜、搜索与筛选无需登录。社区热搜与收藏人数需要登录及本地API；离线不会填充虚构热度。

按用户要求，本地库现已加入明确标记的社区与排行演示数据，不能再将当前榜单解读为纯真实用户行为。账号、数据量和退出演示方式见[演示数据说明](demo-data.md)。最新HAP已支持榜单演示标记。

## 实现范围

- 食材推荐：库存食材进入相关做法页，可继续查看同类；猪肉、牛羊肉、禽肉、鱼虾、蛋、豆腐、蔬菜、菌菇、米面共12组。具体品类与别名匹配保留，五花肉不会混入牛肉分类。
- 筛选：固定分类栏＋固定应用栏；食材全含/任一、排除食材、类别、餐次、菜系、地区、口味、饮食目标、时间、人数预算、难度、我的收藏与排序。组内或、维度间且、排除优先；草稿取消不应用，重置可恢复空结果。应用数量以做法数为单位，同一道菜仍可保留地区变体。
- 搜索：首页和菜谱顶部入口，独立输入页；提交才记历史，规范化去重最多30条，可单删/确认清空。真实七日热搜至少3个不同账号，默认不贡献搜索热度；仅公开字典词可参与。
- 收藏：本机收藏立即生效；在线明确操作贡献真实人数。可按收藏排序，也可显式发布完整本机列表以处理离线变更，版本冲突须重新确认，绝不把旧服务端列表静默覆盖本机收藏。
- 账号：邮箱验证、找回密码、注销入口和后端；单次限时令牌、撤销旧登录、注销依赖阻断及媒体清理队列。本机数据库、偏好、搜索、待同步队列按账号隔离，旧本机数据只归属一次。
- 社区：关注、收藏、关注动态、收藏列表、站内消息、未读筛选、全部已读；撤回与家庭撤权后立即重新判定访问权限。站内消息不等于系统推送。
- 抽餐：锁定某道、只换一道，继续满足菜/汤数量、时间、人数预算、忌口和不喜欢；避免同菜不同版本占多个菜位。
- 来源解析：60道菜谱的器具/标题移出可食用原料，16道菜谱进一步修复，其中4道解析失败菜谱按原始用料重建，其余处理明确错别字或附注，保留原文及未知用量。
- 营养：按已识别原料的生重与编辑参考值估算，每份热量和蛋白质折叠展示；缺失原料明确列出，不代替整菜营养检测。推荐理由按需查看。

## 外部条件及明确边界

- 默认未配置真实邮件通道，界面显示服务未配置；开发出箱仅用于测试，不伪报邮件发送。真实服务需配置邮件供应商。
- 鸿蒙云函数/云数据库尚未部署，用户已选择先完成本地版；现有NestJS/PostgreSQL为本地增强后端。
- 未签名HAP供模拟器；真机签名、相机/相册成功路径、提醒实际送达与桌面卡片实例仍需真机验收。
- 未接入食物照片自动识别AI，不将规则估算描述成图像识别。
- 部分来源未给逐步时长或独立调味用量；保留来源事实和操作状态，不编造精确值。扩展数量不等于已逐道试做。
- 社区列表当前最多100条、成品最多30条，后续大规模运行需游标分页；目录目前内存合并候选后筛选，扩大到数万菜谱前应改数据库检索索引。
