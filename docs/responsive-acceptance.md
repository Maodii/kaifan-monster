# 0.4.3 自适应与比例修复

本轮针对0.4.2仍然存在的压缩、比例失真和放大字体截断，修改实际布局约束，不用把字体整体变小来适配。

## 已确认根因与修复

- 鸿蒙首页透明插画原图1024×498，却指定432×320解码；改432×210，并按原图aspectRatio显示。原来的Contain不能修正已被错误解码的比例。
- 首页和菜谱图像固定宽度挤占文字；现在由onAreaChange读取实际窗口宽度，图片按内容宽度计算，菜谱缩略图在80–124vp间适配。
- 鸿蒙根阅读栏限制760vp，窄屏减小边距；搜索框根据可用内容宽度而非固定屏幕百分比计算，保留居中、最大宽度及分区规则。
- 菜谱标题允许多行；时间/难度不再强制单行省略，文字优先保留正常字号。
- 记餐方式、餐次选择改为可换行；筛选餐次窄屏改两列。共享选择项在横向滚动区保持固有宽度，不被挤成窄条。
- 七日计划/最近浏览按钮取消固定高度，内部文字可换行；设置行采用最小高度且图标不收缩；底部记餐保存栏以两列分配空间和内容高度布局。
- 抽餐搭配移除占位勾号列，不再自动把标签字体压小以塞满一行。
- 安卓侧处理固定头栏和设置行高度、nowrap工具条、像素字体、图片双尺寸约束、正文与固定底栏间距；保持自然图像比例，放大字体后内容可增高、工具条可换行。具体矩阵与源指纹见安卓最终报告。

## 验证

鸿蒙：responsive-build.log为编译证据，responsive-ui-source.json为12项源路由/资源检查；responsive-native.json记录真实布局边界、插画与菜品图的比例、图文不重叠、搜索居中、设置标签边界及表单导航。只使用已经连接的1280px模拟器，没有新启模拟器，也没有保存测试记录。模拟器拒绝浮动窗口参数（10106107），因此没有把鸿蒙其他窗口尺寸宣称为已实测；屏幕宽度变化由窗口监听与约束处理，后续仍应在真机分屏/横屏验收。

安卓：检查320/360/390/430/768/1024、横屏以及1.3倍字体，长菜名、食材、帖子和多标签夹具仅存在测试内存；检查实际图片content-box与naturalWidth/Height比值、文本边界、金额重叠及固定底栏留白。宿主浏览器不是安卓真机。最终源版本、测试计数和APK指纹见android-release.json及响应式报告。

发布：responsive-release.json、responsive-dual-release.json验证0.4.3/code9、当前源指纹、32共享模块和正式图片资源。未改业务模块的24套原有回归以源指纹复用，不声称本轮重新执行全部后端测试。正式包仍只保留outputs中的一份HAP和一份APK。

最终独立校验通过：双包0.4.3/code9与32模块一致，鸿蒙6项真实几何/导航检查通过；Android59组界面回归内含36页面×14条件=504布局组合零失败，另38核心与6生产Java加密互通通过。Android放大字体使用宿主rem模拟，不等于真实WebView textZoom验收。
