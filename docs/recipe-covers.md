# 454道菜专属封面

原生预置4道和扩展目录450道，共454个稳定菜谱ID；本轮新增64道。每个ID对应独立的512×512 WebP正式资源，手绘食物插画由api-image生成。新增封面阶段保留原390张文件与映射；后续品牌迭代按用户要求对全部454张统一去纸底，正式路径与ID映射不变，哈希随透明通道处理更新。分类导航仍使用分类插画；菜谱卡片、详情、选菜与公共目录使用菜谱ID映射。未知或自定义菜谱使用中性菜谱图标，避免套用另一道菜的封面。

正式映射：client/entry/src/main/ets/model/RecipeCoverMap.ets。原图、逐菜原料/步骤提示词、格序和哈希保存在art-source/recipe-covers。原图为52组分割画布（本轮44–51）；接口实际返回尺寸可能不同于请求尺寸，裁切按实际像素，等比缩放并补边，禁止拉伸食物。512是正式资源画布尺寸，不代表原图每格都有512像素原始细节。新增资源严格遵循请求中的 `dish_v3_*.webp` 文件名，按完整ID映射。

主对话核对0–14，协作美术对话核对15–43。核对依据为菜名、主食材、做法成品形态和格序；图片是AI生成插画示意，不能证明菜谱营养或做法准确。老式锅包肉由肉条形态单独重绘为宽扁炸片；米粥与羊肉汤清除了相邻格边缘。原始44组图保留用于编辑，不以修正结果覆盖源图。

验证和浏览入口：work/reports/recipe-covers.json、recipe-cover-main-review.json、recipe-cover-art-review.json、recipe-cover-expansion-art.json、recipe-cover-gallery.html。画廊直接引用客户端正式资源，支持按菜名与分类搜索，无额外图片副本。浏览器检查预期数量读取manifest，覆盖全部图片解码、唯一URL、画布尺寸、新旧菜搜索结果和页面错误；不替代原生设备运行测试。本轮验证结论见独立扩充报告，不将旧390张的报告当作454张的新验证。

修改或新增图片后，在保持视觉核对的前提下运行scripts/recipe-cover-art.py finalize，重新生成映射、同步两端目录imageKey和sourceRevision，然后构建HAP。不要重新accept已修正组来覆盖单格修复；脚本对已accept组跳过处理。模型为gpt-image-2.5-flare，凭据仅由技能脚本运行时读取。

开饭小怪品牌批次的去底脚本为 `scripts/brand-monster-art.py`，从图像边界连通的暖纸色中识别背景，保留封闭轮廓内浅色米饭、蛋白与碗盘；清除不相连的邻格碎片并增加透明安全边距。主轮廓面积不合理时使用柔和不规则纸边兜底，不强行掏空成品。必要原始atlas保留，未复制整项目。该处理不可对已完成的透明资源反复运行；以 `work/reports/brand-monster-art.json` 的当前策略、哈希与校验结果为准。此前390/454不透明版报告仅为历史验证记录。
