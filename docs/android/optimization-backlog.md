# 开饭小怪：实用优化清单（2026-11-05）

范围：现有鸿蒙功能、20项验收、Android新实现及共享后端。以下是增量方向，不把已有的筛选、收藏、计划、计时、社区分页重新当成未实现功能。标注“待实测”的项目是验证任务，不是已证实的性能问题。Android负责本目录；共享代码/API修改需与主对话协调。

本轮已顺手修复：Android未保存表单返回确认与单份账号内草稿、筛选面板改条件时保留输入、计划整天复制去重、补货防重复、账号切换取消旧提醒、前后台计时刷新管理、金额单位显示、拍照方向修正、食材知识及作者主页去除原始JSON展示。这些不计入下面的新增建议；验证结果见 acceptance.md。

优先级：P0为安装使用或数据正确性的放行条件；P1为日常高频收益；P2为后续扩展。S约半天内、M约1–3天、L更长，仅为工作量级，不是交付承诺。平台验证受可用设备影响。

## 优先落地的8项

1. 双端各跑一遍真实设备闭环，先确认相机/相册、重启通知和桌面卡片，避免“代码有入口、设备用不了”。
2. 做一页清楚的同步状态：上次成功、待上传、冲突、被家庭范围阻断，用户知道记录在哪。
3. 食材录入继续做成多选快捷模板：常用数量、保存位置、保质期记忆，减少键盘输入。
4. 买菜过程提供可撤销误操作，防止刚点错就变成库存变更或重复购买。
5. 清晰区分“做了并扣库存”与“只是吃过”，提前预览用量和库存变化。
6. 菜谱结果显示匹配原因与近似搜索标记，减少“为什么推荐给我”的困惑。
7. 照片失败可单张重试，保存原记录；先把耗流量和失败成本降下来。
8. 真机测包体、冷启动和长列表后再定性能目标，保留一份可复用基线。

## 不建议抢先做

- 未核实用量/热量就加“AI精确营养”和照片自动扣库存，会把不确定结果写成事实。
- 已有本地可靠闭环之前增加积分、复杂任务和频繁打卡，不如先降低录入成本。
- 尚无真实性能基线就更换整个界面框架，缺乏证据且容易拖慢双端对齐。
- 自动上传完整相册、默认打开家庭分享、离线伪造认领/点赞成功，都不作为便利优化。
- 每次迭代生成整项目备份或一套新美术。沿用当前正式资源，只保留必要报告和单份最终安装包。
