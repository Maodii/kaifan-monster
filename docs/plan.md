# 食库执行计划

以 `requirements.md` 为需求基线。原生 ArkTS Stage 客户端，本地 RDB 为事实来源；云端为可选增强。所有修改性自动动作必须确认；估算金额明确标注；默认私有；无外部商品库或模型服务。

## 交付顺序

1. 环境：DevEco/SDK/编译工具/本地模拟器；后端容器读写实测。
2. P0 客户端：食材及位置 CRUD、到期状态和仪表盘、模板录入、采购、离线菜谱及确定性推荐、制作确认扣库存、用餐记录、Preferences/RDB、备份、错误/空状态。
3. P0 云端：用户/JWT/设备、数据库迁移、带版本和冲突的变更日志同步、食材/模板/采购/菜谱/用餐 REST API、预签名照片队列、限流和 DTO 校验。
4. P1：家庭权限隔离、图片/相机/Scan Kit、系统提醒、桌面卡片、统计导出、教程计时、草稿及收藏、社区与管理员审核。
5. 交付：断网与异常路径验证、同步冲突/跨用户越权验证、截图、可安装 HAP（依签名条件）、Docker Compose、接口/路由/部署文档。

## 阶段反馈

不以截图审批阻断工作。每个可运行阶段提供真实引擎/设备截图、当前可用内容及限制。截图只写入 `work/screenshots/` 并登记 `work/artifacts.json`。仅维护 `work/task-state.json` 一份进度记录。正式源代码位于 `client/`、`backend/`，本次正式交付包位于 `outputs/`。

## 外部条件

真机签名和上架依赖用户华为账号及设备授权；真实云部署依赖服务器地址和凭据。缺少外部条件时先完成本地可验证代码与部署配置，不把未执行步骤标记通过。

## 后台执行约束

用户补充：尽可能后台运行，不打断其他项目。不再前置窗口、模拟鼠标/键盘或打开IDE/浏览器。编译、测试、开发均优先命令行；界面依赖记录为待办，不阻塞独立开发。
