# 场景与背景的柔化过渡

本轮修正两处原有断点：渐变背景没有被background-color过渡覆盖，以及离线场景图先隐藏旧图再等待新图。实时3D和明确标注的离线预览现共用一套可取消的过渡流程。

- 退出：保留当前实际画面的一张快照，柔化到5px虚化；标称140ms。
- 加载：保持旧画面覆盖，释放旧模型后再解析新模型；不同时缓存两个实时场景。预览图片先解码成功，再替换当前图片。
- 入场：新场景已完成首次渲染后，旧快照淡出，新画面从柔和虚化恢复清晰；标称320ms。
- 背景：直接插值渐变的纸色、边缘色和强调色，不依赖ArkWeb对CSS自定义属性动画的支持；标称520ms，快速切换从当前显示颜色继续。
- 昼夜：主光、补光、局部光、环境强度和曝光同步插值；夜间预览图在入场过程中保留同样的明暗色调。

进度按可见帧推进，每帧最多计入64ms，防止慢帧跳过全部中间态；低性能软件渲染环境中总时长可能延长，不将标称时长当作真机帧率保证。退场和加载阶段暂停旧3D场景的重复渲染，避免在旧快照下面继续做无效工作。

快照最长边上限640px，至多一张；过渡结束后画布缩回1×1并隐藏。没有新增Three.js全屏后处理或第二套场景渲染目标。CSS虚化自身的合成开销取决于设备，低画质和减少动态模式跳过场景虚化。切后台、隐藏页面、上下文丢失、加载失败和新请求取代旧请求，都有明确收尾。转场期间停止对旧模型的拾取，底部场景选择仍可连续操作。

网页入口继续使用 http://127.0.0.1:4318/index.html ，刷新即可加载当前版本。鸿蒙模拟器仍拒绝WebGL，使用明确标注的同源离线预览；本轮修好了该模式的换图过渡，没有声称解决系统GPU策略。实际手机帧率和合成层占用仍需真机验证。


## 本地验证结果

17项转场专项检查、123项原生桥接/场景集成检查、24项当前HAP路由检查及5组最终双端包一致性检查通过。55个当前部件视图已更新。专项检查覆盖延迟模型、快速切换、后台中断、OS减少动态、低画质、模型失败与离线图片失败；源码哈希绑定见work/reports/lobby3d-transitions.json。

一次软件GPU锅盖检查超过原10秒等待，但诊断时最终姿态已正确归位；将该宿主检查延长至20秒后完整复验通过，保留中间姿态和最终归位断言。它不用于证明手机动画流畅度。

实际录屏：work/reports/lobby3d-soft-transition.webm，390×844、55.16秒，浏览器解码首帧与媒体元数据验证通过。录屏保留实际软件渲染和加载耗时，展示三次场景切换与昼夜变化，不是预制或合成动画。录屏脚本的一处参数名错误已修复；失败临时视频已删除，仅保留当前有效成品。

当前Android调试APK与鸿蒙未签名HAP均已更新；HAP已在现有模拟器后台覆盖安装。真机GPU与合成性能、触控及发布签名仍需验收。
