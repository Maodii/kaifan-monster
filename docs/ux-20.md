# 本轮20项体验优化

本轮目标：做法优先；做饭与只记餐两种使用方式均有完整入口。以下为实施和验收清单，验证结果完成后补记。

| # | 原问题 | 改进 |
|---|---|---|
| 1 | 六个底栏拥挤、采购抢占一级入口 | 五个底栏：今日/菜谱/记餐/食库/我的 |
| 2 | 不做饭者仍先看到冰箱 | 设置中持久化独立做饭与外食偏好，今日首页保持统一 |
| 3 | 记餐入口埋在日记里 | 今日首屏直接记一餐 |
| 4 | 外卖/餐馆需反复切换 | 今日外卖/餐馆快捷记餐 |
| 5 | 所有使用者需要一致的今日信息 | 今日餐数、花费、已记录热量摘要 |
| 6 | 常吃菜反复填写 | 最近菜品快速加入记餐 |
| 7 | 日记只有日期筛选 | 增加用餐方式筛选 |
| 8 | 混合实付仍写全部估算 | 汇总区分实付与估算，未知热量显式提示 |
| 9 | 记餐选填内容过长 | 地点、营养、照片和备注可折叠 |
| 10 | 保存按钮沉在表单底部 | 固定记餐保存栏与金额摘要 |
| 11 | 分量长表在做法前 | 做法与关键提示默认优先呈现 |
| 12 | 点一下步骤就被标完成 | 纯阅读步骤卡，不误改进度 |
| 13 | 烹饪时阅读密度不合适 | 专注做菜页，单步大字与前后切换 |
| 14 | 计时需手输且默认10分 | 专注页5/10/15分钟快捷值，显式启动 |
| 15 | 总时长与备料制作可能矛盾 | 统一耗时计算与估算标识 |
| 16 | 无法按可用时间选菜 | 15/30/60分钟与不限时筛选 |
| 17 | 查菜只能按推荐或名称 | 增加耗时优先排序 |
| 18 | 多重筛选后不知道为何为空 | 筛选结果数、一键清空及明确空状态 |
| 19 | 菜卡只突出用料 | 增加做法预览与醒目耗时，来源/用量折叠 |
| 20 | 推荐对不做饭者偏库存、换批无明显变化 | 做饭/外食独立地区目标与评分学习、时间预算、直接负反馈与食材多样性 |

验证状态：20项代码已落地，原生验收部分通过；不能视为全部验证完成。所有用量、时间均为参考；仅浏览做法、切换模式和筛选不会扣库存。

当前证据：native-ux-smoke.json通过五分区、统一今日、直接外卖记餐、固定保存栏、选填折叠、最近菜品、退出保护、持久记录、时间筛选、做法优先与专注步骤。临时便当已清除。native-dual-preferences.json通过独立目标与重启保留。共享算法和目录API测试通过学习隔离、时间预算及单场景清除。

本轮未跑完：场景切换后的今日汇总原生断言、采购路径、最新多菜/分量专项回归与实际系统计时通知。旧专项报告保留供历史参考，不当作本轮通过。模拟器图形故障与有界恢复见work/reports/emulator-recovery.md。
