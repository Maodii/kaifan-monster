# 0.9.13：本机协作与 AI 业务边界

## 新协作入口

- AI 对话 → 更多帮手 → 库存体检：近三天到期、已过期及日期未记录的示例主体库存批次。家庭库存不混入。
- 从具体菜谱进入小怪，展开选菜操作 → 采购清单：按菜谱标注人数，合并同名且单位兼容的重复用量，再核对示例主体库存缺口。过期、日期未知、家庭库存不抵扣；可选用料单独提示，不重复占用库存。
- 同一位置 → 备菜顺序：沿用这份真实菜谱的材料和步骤，展示参考总时长。
- 也可以直接输入“库存体检”“这道菜采购清单”“这道菜备菜顺序”。本机工具不会调用模型或上传库存，不修改采购、计时或业务记录。
- 继续支持“用掉鸡蛋两个”“把这道菜加入我的菜谱”，先预览，再确认，可撤销；新功能没有扩大可执行操作范围。

## 安全边界

1. 服务端 JWT 验证账号和设备状态；访问令牌 15 分钟有效，刷新令牌轮换，撤销设备后不能继续调用。AI 调用不接受匿名身份。
2. 客户端、业务 API、私有 AI 网关分别校验当前请求。拦截已知的提示词注入、伪造角色、零宽/全角混淆、密钥/私钥输入、跨用户导出、破坏性命令及明显非饮食用途。
3. 服务端业务范围门禁在数据库读取和模型调用之前执行；网关单独检查当前问题，不能用带菜名的检索上下文掩盖无关问题。正常烹饪细节由系统业务规则继续约束。
4. 模型无工具执行权限，不能直接执行 SQL、代码、系统命令、任意网络请求或写数据库；模型文字/ID 不会转换为本机操作。可执行操作仅从用户当前输入确定性解析，白名单只有单批库存扣减、保存现有菜谱。跨账号、过期快照、重复提交均受到守卫限制。
5. 私有网关不开放公网端口，使用独立服务令牌；阿里云密钥仅在网关环境中，客户端不包含服务商密钥或入口。模型与上游 URL 由服务器固定，客户端不能覆盖，也不跟随重定向。
6. Redis 原子限额：每账号每分钟 10 次、每日 100 次，全站每日 500 次（按 UTC 日期分桶）；失败关闭。拒绝计数后不增加其他额度，避免超过示例主体限额的请求继续耗尽全站预算。额度按推理尝试计，不按准确账单金额计。
7. 每账号同时一个后台助手任务，最多保留 8 个近期任务/取消标识；全进程容量 64。网关现有并发 2、超时、响应大小、输出 token 上限与熔断继续生效。
8. AI 业务请求体上限 16 KiB，DTO 拒绝额外字段，普通问题最多 600 字；同步和其他业务的大小限制不改变。
9. 默认不发送库存；云端推理需要用户本次同意，库存和上一轮对话分别选择。可疑历史不会继续转发。对话不持久化；接口不回显上游错误和密钥，AI/账号接口禁止缓存。
10. 模型返回文本以非执行内容呈现，现有 HTML/Markdown 转义和链接不自动抓取继续保留。

## 实测与限制

- 共享 ArkTS + 真实 SQLite：读取工具零写入，扣减确认/取消、批次选择、单位、来源保留、去重、撤销、过期快照与注入回归。
- 浏览器宿主：新工具实际按钮、无上传同意下本机读取、拒绝注入后不出现修改按钮；常规 AI/布局回归。
- FastAPI 网关：15 项测试，含两种传输的拒绝路径、固定上游、无任意工具、错误脱敏、限流、超时、真实 HTTP 断流释放。
- 公网 HTTPS 与真实 Redis：未登录/未同意拒绝、非法模型字段拒绝、请求体超限拒绝、普通与任务传输的业务门禁、并发计数、TTL、跨账号全站封顶。只创建临时验收账号，结束后注销，无真实用户业务写入。
- 保留一次真实模型空库存推荐验收，证明业务门禁没有阻止正常推荐；另一次真实模型语义试探确认，在无关数学问题中夹带“午餐”也会被模型拒绝。两次验收账号均已注销。
- 鸿蒙模拟器 0.9.13 覆盖安装，实际点击库存体检并确认空库存文案；未同意上传时注入指令被本机拒绝，无扣减按钮。未修改业务数据，验收后清空本次对话并收起到首页。

业务关键词与注入规则无法穷尽自然语言、编码和诱导变化；系统提示词也不是绝对隔离。即使出现文字层绕过，模型仍没有本机写权限、系统命令和密钥读取能力。当前未实现硬件证明/应用完整性认证；拿到仍有效的用户令牌者可在撤销前占用该账号额度。多账号恶意请求仍可能消耗全站额度并影响可用性，应结合上线规模增加注册验证与风险识别。不能承诺绝对防注入、零盗用或零成本。

用户曾粘贴到聊天的服务商 API Key 应在阿里云控制台轮换；客户端或服务端代码不能让旧密钥自动失效。轮换后的值只写服务器私有环境文件，勿再次粘贴到聊天或打进客户端。
