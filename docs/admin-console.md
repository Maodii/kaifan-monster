# 开饭小怪管理工作台

当前线上入口：https://api.example.invalid/admin/ 。新增功能与统计口径见 [埋点与管理增强](analytics-and-admin.md)。本地开发入口：http://127.0.0.1:3001/admin/（备用3000）。[独立管理员账号与密码](../outputs/admin-access.md)仅保存在本机权限0600的文件中。演示账号没有管理员权限。

## 可用功能

| 页面 | 当前能力 |
| --- | --- |
| 总览 | 普通用户数、在线目录数量、媒体清理待办 |
| 用户 | 账号/昵称/UUID搜索，演示与角色筛选；账号详情、最近会话；撤销普通账号会话；验证管理员当前密码后重置目标密码并撤销全部会话，写入审计 |
| 菜谱 | 按菜名或食材搜索、按类别筛选、分页；修改菜名、地区、分类、口味、人数、费用、备菜/烹饪耗时、主料/调味量和逐步做法；原始来源保留；质量待办筛选、差异预览、发布历史与恢复 |
| 内容审核（目前隐藏，既有访问策略不变） | 公开动态、菜谱/条码投稿、举报；状态筛选、搜索、分页；通过/拒绝/下架、举报成立后下架关联动态 |
| 演示数据（目前隐藏，既有访问策略不变） | 查看真实演示批次和数量；填写准确确认词、处理原因后停用批次，退出公开展示并撤销演示登录与榜单贡献 |
| 使用分析 | 云端活跃、新注册、AI结果/耗时、异常、评价、接口使用；北京时间1/7/30/90天，默认排除管理员与演示账号 |
| 操作日志 | 本工作台写操作的管理员、设备、对象、时间、原因和变更摘要；按操作类型、操作人、目标和原因搜索及分页；页面没有删除日志入口 |

界面支持空结果、读取失败重试、搜索清空、确认取消、步骤编辑、键盘快捷搜索（⌘/Ctrl+K）、窄屏布局与减少动态效果设置。令牌只存在浏览器内存，不写入localStorage或sessionStorage；刷新页面后重新登录。

## 数据行为

- 所有`/api/v1/admin/*`路由先验证登录设备，再依据数据库当前角色检查管理员权限。普通账号仅在前端隐藏按钮不算鉴权，因此服务端会直接返回403。
- 用户搜索不返回密码哈希、登录令牌或私有库存/日记；内容审核不列出示例主体或家庭动态。举报处理可撤回关联内容，但不会展示私有正文。
- 写操作在数据库事务中记录处理原因和操作日志。菜谱编辑按版本检测并发，审核按预期状态检测冲突；冲突返回409，不覆盖其他管理员结果。
- 手工编辑的线上菜谱有独立覆盖标记，后续来源导入和容器重启不会覆盖人工编辑。食材/步骤规范化表、教程摘要与版本历史在同一事务更新。
- 管理端编辑与恢复影响在线公共目录。本轮目录分发接入后，原生端须下载并校验更新成功才收到这些改动；未更新设备继续使用本地版本。
- 库存、用餐日记及家庭空间不属于此管理端的数据浏览范围。没有提供批量导出示例主体数据、管理员提权或账号密码读取功能。
- 旧兼容审核接口保留；本次操作日志覆盖本管理端新接口，不声称所有历史接口已有审计。

## 运行

本机依赖与容器已安装。项目根目录：

```sh
API_PORT=3001 docker compose -f compose.yaml -f compose.app.yaml up -d
```

如已修改后端源代码，先构建更新：

```sh
API_PORT=3001 docker compose -f compose.yaml -f compose.app.yaml up -d --build api
```

基础管理端使用迁移015；本轮编辑历史需要迁移017_editorial_history.sql，发布部署时执行。按用户指定，本机管理账号已设为 `admin`，密码见本机私密配置。该用户名使用独立本地登录接口，仅在 `LOCAL_ADMIN_LOGIN=true` 时启用；普通邮箱登录与注册校验不变。新增本地独立管理账号的幂等引导脚本在`backend/scripts/create-admin.ts`，不会把现有普通账号提升为管理员。无参数时不重置密码；显式 `--local-admin` 仅将已登记的独立本地管理员改为用户指定的 本地私密账号配置，并撤销旧会话。

## 本轮编辑质量闭环

- 菜谱列表增加「所有待核对 / 主料量待核实 / 步骤待细化 / 来源待核对」。缺来源、未知主料用量、短步骤、估算时间及未核实费用会显示明确标记。
- 可编辑主料、调味料、建议量、单位、原始用量、用量来源及推荐依据；未知量保留0。人数、费用、估算标记与备菜/烹饪分钟可编辑，备菜和烹饪之和必须等于总耗时。原始来源及版权字段不会被表单覆盖。
- 先预览逐字段 before/after 差异，再发布；继续修改会取消预览状态。发布仍在服务端检查预期版本，过期内容返回409。预览不修改数据或产生发布历史。
- 发布事务同时更新菜谱、规范化食材检索表、步骤表、教程摘要、覆盖版本与审计；只保存所编辑菜谱的前后版本，不创建全项目或数据库备份。
- 历史每页20项，可翻页、查看差异和恢复。恢复生成新版本，保留此前历史；可恢复到首次编辑之前。过去未保留历史的改动无法凭空还原。
- 接口：`POST /admin/recipes/:id/preview`、`GET /admin/recipes/:id/history?page=1`、`POST /admin/recipes/:id/revert`；列表支持`quality=all|needs-review|quantity|steps|source`。所有路径沿用管理员权限及设备校验。
- 本轮为单管理员「预览—发布」流程，未提供双人审批或自动认证内容准确性。在线目录修改与恢复会被本轮目录增量分发检测到；原生端需成功更新才能获得新内容。
- [API验证](../work/reports/editorial-workflow-api.json)与[浏览器验证](../work/reports/editorial-workflow-ui.json)：隔离真实PostgreSQL及Nest HTTP共9组，包含嵌套DTO、预览无写入、并发、恢复重做、规范化搜索、390px布局、取消恢复与质量筛选。测试账号、schema均已移除，没有改动正式菜谱。
