# 小怪原生操作桥接 0.9.12

## 这次修正

- 鸿蒙顶栏“返回/收起”“新对话/停止”使用固定最小宽度、明确左右内边距且不被压缩；回看时“最新消息”缩为“最新”，给操作留出空间。Android 同步固定按钮 intrinsic 尺寸。
- 空库存不会阻止推荐。已授权的云端库存为空时，仍按人数、时间、预算、地区和忌口筛选候选菜谱，给出采购与补货提示。未共享库存时明确未知，不把未授权当作空库存。本机确实为空时追加本地提示，不需要上传库存。
- 日常做菜回复不堆砌与问题无关的免责声明；相关食品风险仍提醒。Markdown 继续用共享文本块渲染。

## 当前可执行的操作

| 输入 | 行为 |
| --- | --- |
| 用掉鸡蛋2个 / 鸡蛋用了两个 | 匹配示例主体库存，显示扣减前后数量，确认后记录消耗和费用流水 |
| 猪肉减少200克 | 支持 g/kg、克/公斤、mL/L 兼容换算，数量必须明确且不超过库存 |
| 把这道菜加入我的菜谱 | 在当前菜谱上下文生成私房菜保存确认，保留用料、做法、来源 |
| 把番茄炒蛋保存到我的菜谱 | 只匹配真实目录；多个同名/不同地区版本时要求先打开具体菜谱 |

推荐菜卡的“安排”中也有“保存为私房菜”。

所有操作仅在客户端真实数据层执行；模型回复不会变成任意代码、SQL、接口或数据写入。不生成或执行任意模型工具名。操作识别只看当前用户输入，本次支持有限的明确指令，不声称任意自然语言均能正确解析。普通聊天、问做法或举例不会直接执行。

- 不需要云端授权就能提出本机操作，且不会因本地操作自动调用模型或上传库存。
- 每次展示确认卡，点击后再次确认。取消不写入；执行期间防重复点击。
- 同名食材多批次需选批次；没有数量、单位不符、超量、模糊菜谱等先澄清，不猜测。
- 只处理示例主体库存，家庭共享库存不自动扣减。
- 原生 LocalStore 的事务、版本检查、批次流水、费用分摊和同步队列继续复用。
- 确认期间账号、草稿、库存或菜谱变化会拒绝过期操作。
- 保存私房菜不改变公共目录；同一来源不重复加入。
- 撤销扣减会追加恢复流水并恢复数量/费用；撤销私房菜只删除刚保存且未后续修改的那条记录。后续变化或不同账号不允许盲目撤销。
- 本地变更是否上传依然遵守原有同步设置，操作成功不等于已经完成云同步。
