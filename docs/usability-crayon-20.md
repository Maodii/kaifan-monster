# 本轮10项功能与10项美术优化

目标：新用户少填写、容易找到下一步，老用户能追溯食材并快速决定整餐。下列为实施清单，验证状态以末尾报告为准。

| 功能 | 落地方式 |
| --- | --- |
| 1. 三条上手路线 | 首页点选“在家做 / 在外吃 / 整餐帮我选”，设置页可重新打开说明 |
| 2. 消耗后有入口 | 食库增加在库、已吃完、已丢弃、全部批次与搜索 |
| 3. 保留原始购入信息 | 新批次保存购入数量和金额；旧原量缺失明确显示未记录 |
| 4. 部分消耗也可追溯 | 每次手动消耗、丢弃、做菜扣减写事务内历史，展示时间与剩余量 |
| 5. 买过的快速再买 | 历史批次可一键预填新购买，重置日期和到期，确认后才保存 |
| 6. 统一全量教程 | 全部来源读取后按准备、操作、火候、时间、分步取料、完成信号编排 |
| 7. 食材与调味解释 | 豆腐、肉类、米面、油酱醋等品类说明，给口感、选购、替换与注意事项 |
| 8. 每日整餐抽选 | 一菜一汤、两菜一汤、三菜一汤、只抽菜；可设置人数、时间和预算 |
| 9. 不喜欢直接排除 | 独立持久不抽列表，可取消；不依赖学习开关，也不会清除忌口 |
| 10. 抽完直接行动 | 保留今日结果，合并人数备料及库存缺口，逐菜跳教程、一键转采购 |

| 美术 | 落地方式 |
| --- | --- |
| 1. 蜡笔纸感 | 背景轻颗粒，控制明度以保文字对比 |
| 2. 不规则涂抹 | 核心入口使用专门的蜡笔色块，减少规整纯色矩形 |
| 3. 食物成为视觉主角 | 抽菜、结果、步骤头图复用专属390张食物图 |
| 4. 手帐标题 | 局部蜡笔下划线，正文保持清晰系统字体 |
| 5. 多彩但有角色 | 奶油底、叶绿做饭、珊瑚记录、蓝色历史、姜黄随机 |
| 6. 不等半径纸片 | 卡片采用非对称圆角，仍保留稳定点击区 |
| 7. 按钮蜡笔底纹 | 主次操作区分纹理与文字权重，而非全屏同样按钮 |
| 8. 步骤视觉层次 | 大步骤号、短标题、具体操作和次级提示分层 |
| 9. 历史时间线 | 购买与消耗分色，价格与日期对齐，保留食材图 |
| 10. 空状态与进度 | 轻插画与下一步行动，上手及备料进度不单靠颜色表达 |

边界：统一教程不伪造来源未写的克数和火候；人数换算后，原步骤固定数量需以新清单核对。外食时间与费用使用用户设置的估计，不冒充餐馆实时报价；云端跨设备同步仍按现有功能边界。

## 实测与限制

本轮已实现上述20项。386条导入菜谱共3786个统一步骤，另4道内置菜使用同一模板；配套30项食材/调味知识与390张独立菜图。合并备料按人数换算，库存仅计未过期在库量，转采购会减去已在待购清单中的同单位数量。

通过：ArkTS构建；整餐约束及全386教程一致性；实际LocalStore代码搭配临时SQLite的购买、消耗、做菜、回滚、用完、丢弃、重启回读及备份测试；真实API历史同步及非法流水拒绝；鉴权、媒体与目录集成测试；无头浏览器抽菜/排除/示例历史/教程交互与截图。

时间按各菜备料及制作总时长相加，不假定同时开火。外食按自设往返、候餐、用餐总时间及人均费用估计。做饭费用无有效菜谱价格时，使用食材基础单价和分量规则粗估；不能识别主要食材或单位时不当作免费，有预算限制则排除。无法找到组合时明确提示调整条件，不自动超时或超支。

新界面原生运行回归未完成：已有模拟器出现EGL/Cocoa图形故障，无可用hdc目标。本轮截图为使用真实菜谱与共享算法的浏览器交互预览，历史页为示例数据，不是设备实拍。诊断见 `work/reports/emulator-recovery.md`。
