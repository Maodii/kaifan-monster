# 菜谱、餐次与社区美术交付

本对话负责美术，主开发对话 `01a19f30-f4fc-7823-8b17-045904cf2911` 负责业务、接入和原生验证。此批不覆盖现有390道菜图、30个功能图标或字体。

## 分类与筛选建议

- 餐次独立于菜品分类：早餐、午餐、晚餐、加餐；一菜可用于多个餐次。首页默认“全部”，选中状态须有文字与轮廓，不能仅靠颜色。
- 菜品类型沿用家常、汤粥、主食、凉菜、甜点等；不要把“早餐”同时当成互斥菜系。旧数据需要兼容映射，由主任务实现。
- 筛选分组推荐按“今天哪餐 → 有多少时间 → 想吃什么 → 饮食目标 → 现有食材”排列；地区、口味等放展开区。缺失数据不得推断成低脂、高蛋白或过敏安全。
- 同一维度多选取并集，不同维度取交集；有相互排斥的时间区间时用单选。面板使用草稿，应用后才更新列表；取消保留已应用条件，重置清空草稿，应用结果在列表上方以可删除条件条呈现。
- 零结果提供“放宽耗时”“清空筛选”等实际动作；数量与条件摘要使用原生文字；不能在插画中画死计数。

## 首页与社区入口

首页建议保持“餐次入口 → 今日做饭主操作 → 菜谱推荐 → 餐桌广场预览”的阅读层级。横幅只作为社区模块的引导配图，不代替入口标题、说明、按钮或真实帖子。帖子照片应来自实际用户上传，不能用生成插画冒充。

社区状态必须区分：未登录、已登录暂无动态、筛选无结果、网络失败、发布编辑、待审核。图像为辅助，所有状态均保留原生标题、说明和可操作按钮。待审核不能显示已发布成功或审核通过图标。空状态不能覆盖有错误的状态，首次加载使用真实加载指示器。
