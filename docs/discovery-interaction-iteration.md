# 菜谱浏览与搜索交互迭代

本轮以最终 work/reports/discovery-release.json 为验收入口；开发期间报告可能尚未生成。

## 页面与数据

- 菜谱分“菜谱大全”与“为你推荐”。大全只使用硬筛选与忌口，稳定排序；近期吃过、浏览反馈不会把菜隐藏。只有推荐保留“换一换”。
- 大全与筛选结果连续向下滚动，接近尾部自动接续24道，不需刷新或点加载按钮；同菜多个已有做法归为一组，全部独立ID保留并可在详情切换。
- 支持综合、价格升/降序、耗时升/降序。价格依据卡片显示的同一份预测数值排序；未知耗时两种方向都放最后。
- 详情返回菜谱保留当前条件、排序、已加载数量、可见菜品和滚动位置。打开详情所记录的浏览反馈不触发列表重排；主动换条件、实际库存/用餐变化才重新计算。
- 分类、场景、最近浏览、对比、写菜谱与公共菜谱收纳到“更多”；首屏保留搜索、筛选、排序和菜品，减少重复说明。外食费用标明家常参考，详情可点费用查看估算依据。
- 抽餐开始前可见独立筛选及其摘要，支持菜系、餐次、类别等条件；不改变菜谱大全筛选。抽取条件在本机保存。
- 九类导航明确采用八大菜系＋其他地方菜，通用家常、异国风味与缺失元数据不硬塞进地方菜分类，不限条件下仍保留。两条带明确地域名的红烧肉元数据按原来源标题修正：徽派→安徽、湖南家常→湖南。
- 菜图改用固定方形Contain并禁止Row压缩；源atlas被邻格切开的图片由美术对话恢复盘沿、隔离主体，正式变更以独立报告为准。

## 搜索

缓存离线菜谱索引，先应用忌口、收藏和用户筛选，再进行搜索召回。支持中文拆词、全拼/分音节/首字母、同音字与有限编辑距离；支持明确的不辣、排除或包含原料及中文数字时限。无效时限与矛盾条件明确报空，不绕过约束推荐。保持原输入，精确命中优先。没有直接匹配时明确提示并展示受同一组约束的灵感，不将推荐冒充匹配；输入过程只显示页内说明，提交才提示一次。原生增量渲染显式以当前输入驱动提示计算，避免完整拼音已匹配而说明仍停留在输入首字母的回退状态。

算法细节、评测与HTTP范围分别见 recipe-discovery.md、recipe-fuzzy-search.md。原生离线新检索已接入，现有HTTP目录仍有旧SQL筛选/分页边界，未宣称服务器搜索与新离线检索完全等价。

## 验证

原生专项脚本 scripts/native-discovery-ui.py 和 scripts/native-discovery-search.py 检查排序、返回位置、九类菜系、四种既有红烧肉做法、抽取筛选重启保存、连续加载，以及拼音/错字/相似结果提示。仅改变本机测试搜索/最近浏览元数据，不新增库存、用餐或计划；新增抽取筛选条件测试后撤销。

固定图库与HAP资源、两端目录、模块镜像、真实数据库种子更新、后端构建和本地健康检查在发布报告分别记录。硬件相机、系统通知与真机签名沿用已有专项待验状态。
