# 原生页面与数据路径

全部页面使用ArkUI，入口 `entry/src/main/ets/pages/Index.ets`，由本地状态控制视图；不存在WebView或Web客户端替代。

| 入口 | 页面状态 | 主要行为 |
|---|---|---|
| 今日 | tab=0 | 使用模式、直接记餐、外卖/餐馆速记、每日摘要；做饭模式另显示食库 |
| 食库 | tab=1 | 搜索/分类/位置/排序、食材编辑、消耗、批量、采购入口 |
| 采购（食库内） | shopping | 添加、分组、确认购买、转库存、清理、导出 |
| 菜谱 | tab=3 | 离线规则推荐、口味、收藏、示例主体菜谱、公共菜谱 |
| 记餐 | tab=4 | 日期/方式筛选、最近菜品、实付与估算、示例主体热量、统计与分享 |
| 我的 | tab=5 | 双场景推荐偏好、账号、偏好/分类默认值、位置、云端、提醒、备份 |
| 食材录入/编辑 | food | 两步点选，模板预填、数量快捷值、位置选择、日期日历、可折叠选填、固定保存栏 |
| 实际消耗 | consume | 输入实际数量，二次确认 |
| 食材模板 | templates | 散装预设，始终进入确认表单 |
| 做法详情 | recipe | 耗时与完整做法先展示，用量/采购及来源按需展开；可只记吃过 |
| 专注做菜 | cook-guide | 单步大字、阅读进度、前后切换、显式系统计时，不改库存 |
| 自定义菜谱 | recipe-edit | 私有菜谱/用料/步骤CRUD |
| 公共菜谱 | public-recipes | 审核通过列表，确认保存私有离线副本 |
| 手动用餐 | meal | 餐次点选、估算金额、备注、相册/拍照，不扣库存 |
| 补货建议 | replenishment | 已吃完/余量不足，逐条确认采购，排除丢弃 |
| 统计 | stats | 日周月、餐次、累计消耗/浪费估算、CSV |
| 账号/家庭 | account | 设备/解绑/命名、修改密码、创建/加入/解散家庭 |
| 生活广场 | community | 公共/家庭/我的发布，私有数据不出现在公共feed |
| 动态 | post | 照片签名读取、点赞/取消、评论、举报、撤回 |
| 分享范围 | publish | 家庭或公开待审，价格独立开关、二次确认 |

底栏顺序固定为今日、菜谱、记餐、食库、我的。采购从食库进入。旧内部tab编号保留用于兼容，用户界面不展示编号。

## 原生系统入口

- `EntryAbility`：接收 `foodId` 打开指定食材；`shoppingId` 打开采购并确认已购买。
- `PantryFormAbility`：提供 `ExpiryCard`、`ShoppingCard`（2×2/2×4），从Preferences接收本地快照；卡片动作跳转原生确认，不静默改库存。
- Scan Kit：EAN13、UPC-A/UPC-E系统扫码；只使用本地私有模板或自建服务端目录，未命中进入可编辑表单。
- 系统PhotoViewPicker/CameraPicker：临时媒体授权，复制原图及生成JPEG压缩图到应用files目录。
- BackgroundTasksKit提醒代理：用户启用后本地系统提醒、到期重复和烹饪计时。受系统权限/配额限制，见验收表。
- DocumentViewPicker：JSON/CSV/文本的用户选择导入导出；不硬编码外部文件位置。

## 本地数据

`shiku.db` 的 documents 表以(kind,id)为主键，记录和待同步变更日志在同一事务写入。Preferences保存设置、稳定本机deviceId、同步游标、卡片快照；AssetStore保存会话。云端entity版本和用户全局游标分离。照片原图/压缩图路径不上传到其他设备，远端合并保留当前设备自己的路径。

补充原生页：逐字段冲突合并`merge`、作者公开主页`profile`；日记页内置月份日历，设置页可切换主题及原子改名存放位置，家庭成员页提供管理员邀请码管理。
