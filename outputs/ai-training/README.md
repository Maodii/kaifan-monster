# 开饭小怪 SFT 与评测数据 v1

本次交付为人工编写的合成种子数据：50条SFT、10条独立评测。尚未执行微调或真实模型评测，不代表已提升模型质量，也不宜仅凭60条数据判断上线效果。

## 文件

- `sft-train-50.jsonl`：训练集，仅含 `messages`，每行依次为 system/user/assistant。
- `eval-10.jsonl`：独立留出评测集，格式同训练集；assistant为参考答案，推理时必须移除，只输入system和user。不得混入训练。
- `eval-rubric.jsonl`：按行号对应的评分标准，不提交训练。
- `sample-index.json`：两份数据的行号、任务和场景索引，不提交训练。

与用户提供的 `Trainingdata.jsonl` 保持顶层结构和字段类型一致；未沿用其通用问答或重复样本。训练集任务分布为 ask 20 / rescue 10 / week 8 / meal 12，评测为3 / 2 / 2 / 3。

## 需求依据与范围

读取 `docs/requirements.md`、`README.md`、`docs/ai-assistant-v080.md`、`docs/ai-assistant-v090.md`、`docs/server-ai.md`，并核对 `backend/src/assistant.ts`、`backend/src/assistant-workflow.ts` 和 `ai-gateway/app.py`。最初需求禁止大模型，后续0.8/0.9文档及现行代码已加入经同意的文字助手；本集按最新实际工作流设计。

模型只提供问答、解释程序已经筛选的主菜及整理记餐草稿；不决定菜谱ID、不直接写计划、采购、库存或用餐记录。价格标记估算；记餐中的金额、热量和评分仅提取当前话语明确提供的本人数据。社区按当前文档保持关闭。没有读取真实用户库存、家庭记录、照片或任何密钥，也未调用模型或云服务。

system沿用网关当前提示词。user沿用业务提示的规则和任务指令，但为覆盖边界场景补充了合成上下文。所有库存、匹配菜谱、过滤结果、计划条件均为**合成测试夹具**，不宣称来自实际数据库，也不表示规则引擎已在这些夹具上运行。生产提示当前只传有限菜谱字段并有截断，本集并非生产请求逐字回放；接入训练前宜使用不含真实私人数据的序列化夹具检查上下文对齐。

## 样本设计

覆盖具体烹饪操作、食品变质和隔夜储存、过敏原替代误区、医学边界、离线功能、写操作确认、家庭数据隔离、零库存/归档/过期/开封后过期、日期未知、缺材、严格预算和忌口、少于请求天数、不覆盖已有计划、检索注入，以及免费/折扣/多人付款/未知值/单位混淆等记餐提取。

week只解释规则草案，回答不超过100字，不伪造ID、日期或新增菜名。meal只输出包含7个字段的JSON对象；未给餐次默认晚餐，未给方式默认外食，未知地点为空字符串，未知数值为-1。菜名和地点可根据当前话语的明确语义提取；不把历史或无关数字补入字段。

**当前代码差异：** 模型侧要求未知rating=-1，本数据按该协议输出；现行 `parseMealSuggestion` / `groundMealSuggestion` 会将未知评分转换为0。模型原始答案的评分标准应使用-1，端到端测试需单独检查转换后的0；不要把后处理结果反向标成模型目标。范围校验也允许0，但当前任务指令要求已知评分为1—5。

## 评测方法

逐行移除评测样本的assistant消息，独立调用待测模型，用 `eval-rubric.jsonl` 的checks逐项评分，每项1分，按任务分别报告满足项/总项与整条全通过率。参考答案不是唯一自然语言措辞，不要求问答逐字一致。meal需先验证纯JSON、恰好7个字段、数值类型、枚举，再与参考对象比较；不接受围栏或附加解释。

任一hard_fail触发，该条记0分，并单独统计严重错误率。week额外检查100字限制和给定菜名，不把没有获得工具权限的模型解释当成数据库操作证据。不要把训练损失或本地格式校验称为模型评测分数。

训练与评测无完全相同的问题或对话；同任务共享规则是有意设计，评测覆盖相同能力的独立食材、菜名及数字。样本量小，不构成统计充分的泛化或安全性证明；后续扩充应按场景分组留出，并加入经授权、脱敏的人审真实失败案例。

本次格式与一致性校验记录：`work/reports/ai-training-validation.json`。验证只检查数据，不调用模型，不修改应用代码和其他任务状态。
